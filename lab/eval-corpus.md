# 大批量评测数据集 v2

## 规模与用途

数据文件位于本地 `lab/datasets/agent-eval-v2/`，原始数据与运行轨迹不提交；指纹及隔离审计提交在 `lab/eval-corpus-v2.lock.json`。这是回答核验器数据集，不是18,396条端到端Agent任务，也没有执行模型权重训练。

| 数据来源 | 开发集 | 验证集 | 封存测试集 | 总计 |
|---|---:|---:|---:|---:|
| 业务时序合成 | 2,240 | 480 | 480 | 3,200 |
| RAGTruth自然回答 | 11,013 | 2,700 | 1,483 | 15,196 |
| 合计 | 13,253 | 3,180 | 1,963 | 18,396 |

开发集用于修改提示与架构；验证集用于比较候选；测试集只在最终冻结后使用，不能根据其结果继续调参并仍称其为未见测试。现有12条迁移诊断、8条开发诊断不混入新测试集。

## 独立性和污染控制

业务集有100个企业/表格组，70/15/15分配到三个集合。每组8种工作流、正反各一、中英文各一，32条。8种结构为当前读取、写入冲突、清空未知、刷新超时、更新读取、其他表修改、混合表格与单元格注入。组间表ID及数值不同，但模板共享，所以3,200条不等于3,200种独立推理任务；业务验证集只有15个实体组，不能用行数伪装场景多样性。

RAGTruth使用已锁定提交c103204b9ce28d6bbad859304bf30de72b8ed8fe，quality=good。2515个上游train来源与450个test来源对应的17617条可用回答是输入池，不直接全部当作新测试。

- 排除已有评测接触的300个来源，并额外排除原封存100条对应的100个来源，原封存集继续不运行。
- 按真实参考正文内容哈希分组；QA使用passages，避免同一证据段落因问题不同而跨集合。
- 同一参考组若出现在上游train/test两侧则排除；相同参考与规范化回答去重，真值冲突的重复项排除。
- 新开发/验证来自未接触的上游train，按参考哈希80/20划分；新封存测试仅来自未接触的上游test。
- 保留同一来源的多个不同生成回答，但全部留在同一集合。15196条回答来自2564个参考组，分为1855/459/250组，不能将它们当作15196份独立原始材料。

全体2664组（2564参考组+100实体组）跨集合重叠0；案例ID唯一，精确模型输入指纹跨集合重叠0。检查仅检测已知ID、正文等值和输入等值，不保证识别所有近重复、互联网预训练污染或未保留的历史运行。污染审计包括旧结果manifest、旧开发ID，以及后续新版公开数据批量运行的完成记录。

标签仅在顶层评分记录中，模型输入只使用state与draft；RAGTruth不注入标注、原生成模型名或split。公开数据沿用现有适配：参考映射为成功workspace.read，回答追加来源路径；positive表示存在任一标注幻觉跨度，包括上游implicit_true口径。这是适配后的回答级诊断，不是官方跨度级成绩。RAGTruth仓库内MIT许可证保留在本地数据源。

## 构建、复现与批量运行

在仓库根目录、使用后端Python运行：

```powershell
python lab/build_eval_corpus.py
python lab/test_eval_corpus.py
python lab/run_corpus_eval.py --dataset synthetic --dry-run
python lab/run_corpus_eval.py --dataset ragtruth --dry-run
```

构建不会覆盖已有目录。精确复现已冻结的污染排除列表，而不是按最新运行重新划分：

```powershell
python lab/build_eval_corpus.py --audit-lock lab/eval-corpus-v2.lock.json --output lab/datasets/agent-eval-v2-rebuild
```

已实际重建并确认六个文件SHA256全部一致。若追加公开数据评测后要重新划分，则构建新版本；不能悄悄改变v2的分组。

```powershell
python lab/run_corpus_eval.py --dataset synthetic --split validation --concurrency 4 --output lab/results/<新业务验证目录>
python lab/run_corpus_eval.py --dataset ragtruth --split validation --concurrency 4 --output lab/results/<新公开验证目录>
```

入口验证数据文件指纹，逐条落盘，每25条更新原子摘要；中断后用相同参数加 `--resume`。恢复时要求选择列表、模型、接口指纹、验证器源码、运行器源码完全一致；已完成错误也保留，不静默重试以美化成绩。JSONL损坏会明确失败，不宣称能修复任意进程崩溃造成的半条写入。

默认不接受test运行；最终冻结后才显式指定 `--split test --unseal-test`。这只是操作层防误跑，不是访问控制或加密封存。本轮没有使用该开关。

摘要区分误批准FN、误拒FP和执行/合同错误；错误计入总体错误率，不伪装成正确拒绝。另报告场景分项、按参考/实体组的宏平均、模型/时间审核调用数、token。失败样本保存完整脱敏调用供审阅，其余样本保留裁决、引用与用量；不提交原始轨迹。

## 数据质量修订

v1首轮480条只是质量预检，不作为正式能力结论：请求模板要求报告库存、预算和状态，而部分用例仅提供库存，混淆任务完整性与事实真实性。保留v1锁文件与结果，不覆盖。

v2仅修正请求范围为“只核对草稿已讨论的指标，不要求补充未讨论指标”，正反草稿、业务组、分组边界和公开文件不变；没有修改Agent或验证器。生成器、5项数据/入口检查及六文件精确复现均通过。后续如发现真值错误，应新建数据版本，不能改原结果或为提高成绩而删失败项。

## 运行状态

480条业务验证集已完成实际模型评测：412正确、65误拒、0误批准、3合同错误，总体正确率85.83%。结果及限制见[大批量首轮报告](experiments/2026-10-22-large-corpus.md)。2700条公开验证和1963条封存测试尚未运行。开发集不代表已训练模型；数据规模增加也不等于架构已经改善。
