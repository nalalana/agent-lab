# Runtime Skills Audit

## Scope

This document records what the current repository can prove about the
Transparent Company skills pipeline, and what it cannot yet prove.

Step 5 is an audit step. It does not claim that native OpenClaw already
consumes `skills.json` during agent execution.

## What The Platform Model Already Contains

The platform-side skill model is defined by:

- `TransparentCompanySkill`
- `TransparentCompanyAgentSkillBinding`

The runtime preview builder lives in:

- `backend/apps/runtime/services.py`

The relevant build steps are:

- `OpenClawConfigService._build_skill_item`
- `OpenClawConfigService._build_binding_item`
- `OpenClawConfigService.build_company_preview`

At this layer, the repository can prove that the backend collects:

- platform skill catalog items
- agent-to-skill bindings
- permission templates
- agent permission bindings

and exports them into the runtime preview payload.

## Runtime Export Materialization

The shared-host bridge materializes runtime artifacts in:

- `scripts/runtime/shared_host_bridge.py`

The main materialization path is:

- `_sync_native_agent_state`

Per agent, the bridge writes these files:

- `agent.json`
- `skills.json`
- `permissions.json`
- `knowledge.json`
- `AGENTS.md`

The bridge also builds native runtime config through:

- `_build_native_openclaw_config`

So the repository can prove that skills-related data is written into
runtime-managed export files.

## Confirmed Runtime Inspection Capability

An admin-only inspection endpoint is available at:

- `GET /api/runtime/inspection/agent-exports?cid=<cid>`

It returns a safe summary of runtime export artifacts for each agent,
including at least:

- `agent_id`
- `agent.json` summary
- `skills.json` existence and item count
- `permissions.json` existence summary
- `knowledge.json` existence summary

The endpoint is implemented through:

- `backend/apps/runtime/views.py`
- `backend/apps/runtime/urls.py`
- `backend/apps/runtime/services.py`
- `scripts/runtime/shared_host_bridge.py`

This inspection is intentionally summary-only. It does not return raw file
contents, host absolute paths, or sensitive runtime payloads.

## Repository-Only Boundary

The visible CLI entrypoint is built in:

- `backend/apps/runtime/security.py`

through:

- `build_openclaw_agent_exec_command`
- `build_openclaw_agent_stream_command`

These commands execute native OpenClaw in the form:

```bash
openclaw agent --agent <id> ...
```

However, the current repository snapshot alone does not prove which internal
files the native OpenClaw binary consumes after that command starts.

In particular, the current repository does **not** prove that native OpenClaw
reads `skills.json` during execution.

## Runtime Package Confirmation For `openclaw@2026.3.11`

The shared-host runtime image generated by this repository installs:

```bash
npm install -g openclaw@2026.3.11
```

After inspecting the published `openclaw@2026.3.11` package, the confirmed
skills consumption path is:

1. `cfg.agents.list[].skills`
   This is read as the per-agent skill filter through `resolveAgentSkillsFilter`.
2. `buildWorkspaceSkillSnapshot(workspaceDir, ...)`
   This loads real skills from workspace-visible skill directories, including:
   - `workspace/.agents/skills`
   - `workspace/skills`
   - managed and bundled skill roots
3. Session refresh
   `session-updates` rebuilds `skillsSnapshot` when the watched `SKILL.md`
   paths change and the snapshot version advances.

This means the confirmed native consumption point is **not** `skills.json`.
The confirmed native consumption point is:

- native agent config `agents.list[].skills`
- workspace materialized `SKILL.md` directories

## Proven vs Unproven

### Proven

- Platform skill catalog can be serialized into runtime preview config.
- Agent skill bindings can be serialized into runtime preview config.
- Shared-host bridge writes `skills.json` into runtime-managed agent export
  directories.
- Admins can inspect per-agent runtime export summaries through the inspection
  endpoint.
- For runtime package `openclaw@2026.3.11`, native OpenClaw consumes
  `agents.list[].skills` and workspace-visible `SKILL.md` directories.

### Not Proven In This Repository

- Native OpenClaw definitely reads `skills.json`.
- Native OpenClaw uses `skills.json` to control runtime behavior.
- The exact internal consumption point for skills inside the OpenClaw binary.

## Current Blocker

Current repository evidence still does not prove consumption of `skills.json`
by native OpenClaw.

Step 6 is only valid after switching publication to the confirmed native
consumption point:

- `agents.list[].skills`
- workspace `.agents/skills/<skill>/SKILL.md`
